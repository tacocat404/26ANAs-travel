- **사용자 프롬프트(요약)**: 친구들과 여행 일정을 짜는 캘린더 앱. 날짜 클릭으로 각자 "안 되는 날"을 색깔로 표시, 비밀번호 없이 이름만으로 로그인. 여행별로 분류하고 지도(후보지)·갤러리·공지 기능 추가. 시니어 개발자 관점으로 기획해 달라. 기획→디자인→구현 순서.
- **Claude의 변경사항**: `docs/PLAN.md` 작성 — 핵심 기능 6개(F1~F6), 설계 결정("안 되는 날"은 사람 기준 전역 저장, 저장소 2단 구조: 데모 모드↔Supabase 공유 모드), 화면 흐름, 디자인 방향(모바일 우선·크림+산호색), 로드맵.

### [구현] 앱 전체 구현 (데모 모드 완동)
- **Claude의 변경사항**:
  - React + Vite 프로젝트 생성. 화면: 이름 로그인 → 여행 목록 → 여행 상세(캘린더/지도/공지/갤러리 4탭).
  - 캘린더: 날짜 탭 = 내 "안 되는 날" 토글(내 색으로 칠해짐), 친구들은 색 점, 날짜 선택 시 안 되는 사람 이름 표시.
  - 지도: Leaflet + OpenStreetMap, 탭해서 후보지 핀 추가/삭제.
  - 공지: 작성·📌 고정·작성자만 삭제. 갤러리: 사진 자동 압축(1000px JPEG) 업로드·확대·삭제.
  - 저장소: `src/store.js` — localStorage(데모)와 Supabase(공유)를 같은 인터페이스로 구현, `src/config.js` 키 유무로 자동 전환. DB 스키마 `supabase/schema.sql` 준비.
  - 브라우저 자동 테스트로 전 기능 검증(로그인, 여행 생성, 날짜 토글·색 점, 후보지 추가, 공지+고정, 사진 업로드). 프로덕션 빌드 성공.
- **다음 단계**: ① 운영자가 Supabase 프로젝트 생성 후 키 전달(`docs/SETUP.md` 1단계) → 공유 모드 전환. ② GitHub 저장소 + Vercel 배포(2단계). ③ 이후: 후보지 투표, 전원 가능일 자동 추천.
